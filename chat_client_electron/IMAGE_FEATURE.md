# 图片功能运行与排查

本地消息和图片缓存的实现、当前验收状态及部署前提见 [本地存储说明](LOCAL_STORAGE.md)。

研究发送、加载、存储及失败恢复流程，见 [图片功能链路图](IMAGE_FLOW.md)（含 Mermaid 图和代码入口）。

在本目录运行 `npm run dev`，直接连接服务器，不需要先启动 SSH 隧道。

聊天入口是 `39.105.18.142:7000`，文件入口是 `http://39.105.18.142/media`。服务器 Nginx 将文件请求转发到回环端口 6002，仍由业务服务检查授权，图片文件不通过公开静态目录暴露。云安全组须允许入方向 TCP 7000 和 80。公网 HTTP 仅用于当前学习联调，文件和凭证明文传输。

选择联系人后点击“图片”，支持静态 JPEG / PNG，最大 20 MiB、2400 万像素。缩略图自动加载，点击查看原图；失败时保留占位并提供重试。发送过程区分准备、上传、服务端处理和消息确认。关闭程序或断线后，“待发送”中保留任务，重新登录后点击重试即可继续。

运行依赖位于 `resources/native/`：`chat_image.exe` 与 `opencv_world4130.dll`。它们是 C++ 媒体项目的构建产物，被现有 Git 忽略规则排除；在其他机器运行或打包时需要复制。可以用 `CHAT_IMAGE_TOOL` 指定另一份已经安装依赖的绝对路径。

主进程使用 `CHAT_HOST`、`CHAT_PORT` 覆盖默认的 `39.105.18.142:7000`，`CHAT_MEDIA_URL` 覆盖明确允许的公网 HTTP 文件地址（包含 `/media`）。图片任务与缓存放在 Electron userData 下，按服务地址和账号隔离。更换服务地址会进入另一份本地缓存与任务目录，服务器历史记录仍可重新同步。

| 现象 | 检查位置 |
| --- | --- |
| 登录连接失败 | 公网 TCP 7000 是否可达，服务器 Nginx 和 chatserver.service 是否 active |
| 上传到 100% 后仍等待 | 文件已发出，仍需服务端校验与消息事务确认；超时后从同一任务重试 |
| 票据失效、原图失败 | 点击重试，会重新授权并下载；不要保存临时票据 URL 到历史记录 |
| 图片工具不可用 | 检查 exe、OpenCV DLL 及运行库；界面会保留任务并提示处理失败 |
| 断线后出现“待继续” | 重新登录同一账号，打开“待发送”重试；本地源文件副本仍保留 |
| 删除好友后还存在失败任务 | 从“待发送”入口取消；不需要恢复好友才能删除自己的任务 |

测试入口：`tests/tcp.test.js`、`tests/image_transfer.test.js`、`tests/image_processor.test.js`，以及连接真实隔离服务的 `tests/image_client.test.js`、`tests/image_window.test.js`。窗口测试使用独立 userData，不读取个人登录信息。

图片交互取舍和服务端对应代码见服务端项目 `docs/chat-image-client-details.md`。视频、动图、粘贴/拖放、分片续传和 OSS 不在当前实现范围。

普通文件链路、使用方式与部署前提见 [文件功能说明](FILE_FEATURE.md)。
