# 视频消息功能方案

状态：待实施。本文保存视频消息设计，不代表功能已上线。

## 首版范围

- 复用现有媒体传输、任务、消息同步和本地缓存。
- 单视频上限 100 MiB。建议先支持 MP4 容器、H.264 视频编码、AAC 音频或无音轨；由服务端检查实际内容，最终以所用 Electron 版本实测确认。
- 完整下载并校验后播放，不做远程边下边播、断点续传或自动转码。
- 不支持内嵌播放的格式仍可通过普通文件入口发送和保存。
- Electron 使用内置 video 元素，不开发独立 C++ 播放引擎。

## 发送与处理

选择视频 → 私有副本和摘要 → 共用上传 → 服务端校验 → FFprobe 提取信息、FFmpeg 生成封面 → 消息确认 → 历史与本地缓存。

复用进度、取消、重试和 client_msg_id/message_id。增加 video 消息类型与名称、时长、宽高、编码信息及原视频和封面资源关联。文件内容保存在对象磁盘，MySQL 保存元数据。

上传 100% 后显示“正在处理视频”，处理成功后才确认发送。正在处理不能直接当作上传失败重传；客户端需等待或查询处理状态，并处理超时、取消及重连后的状态恢复。

服务端媒体处理采用独立子进程、单任务并发、有限队列及处理超时，不阻塞网络线程、不将整段视频一次性读入内存。仅允许处理受控本地文件，使用参数数组调用程序，限制资源占用，失败时清理未完成产物。

## 展示与播放

- 气泡显示封面、时长、大小和播放按钮。
- 历史加载只同步元数据及封面，不自动下载视频正文。
- 点击播放时先验证缓存；缺失或损坏时下载，展示百分比，允许取消和重试。
- 下载校验完成后由 video 元素提供播放、暂停、拖动、音量和全屏。
- 支持另存为，保存副本不受缓存清理影响；播放失败提供提示与保存入口。
- 本地播放地址由主进程授权，支持播放器拖动需要的本地 Range 读取，不暴露任意磁盘路径。
- 播放期间保护缓存文件，关闭播放器后释放资源与缓存保护。

## 实施顺序与验收

1. 后端迁移、格式检测、封面处理、状态接口。
2. 客户端视频任务、卡片、缓存与播放器。
3. 验证正常视频、无音轨、旋转视频、不支持的编码、损坏文件、处理超时、取消重试、离线播放，并回归图片和普通文件。
4. 本地通过后部署，沿用现有端口与 SSH 隧道。

## 与流媒体学习的区别

该功能是视频文件消息，并非 RTSP 实时拉流。流媒体学习可以另设本地 C++ 拉流录像模块，录像完成后接入现有文件/视频发送链路；无需把现有聊天服务器改为流媒体服务器。
